## Summary

Of the 23 original findings and candidates, 18 are resolved, four remain open,
and one is partially resolved. The current statuses are listed below with their
original severity unless otherwise noted.

## Original confirmed findings

### HIGH

**1. Batch writes bypassed field-type semantics — Resolved.**
`multi_field_update` and `multi_field_fast_write` now reject transient fields
and raw values for encrypted fields. Encrypted batch values must be `nil` or a
`ConcealedString`; regression coverage verifies rejection, ciphertext storage,
and nil deletion. This resolves the original plaintext/transient persistence
risk. A separate `multi_field_fast_write` index-integrity defect is recorded in
the [2026-09-04 delta audit](2026-09-04-audit.md).

**2. `category_score_range` ignored its category — Resolved.**
The method was removed because a permission bitmask category cannot be
represented as a contiguous sorted-set score range. No production callers
remain; callers must use `score_range` then `filter_by_category` or
`meets_category?`.

**3. Permission API failed open on unknown symbols — Resolved.**
Permission lookup now raises `ArgumentError` for unknown symbols throughout the
flag-taking API, including permission mutations and range queries. The
permission API has focused regression coverage.

### MEDIUM

**4. `decr` / `decrby` raised on every call — Resolved.**
Both use `HINCRBY` with a negated amount and are covered in the Horreum command
tryout.

**5. `encryption_info` raised on every call — Resolved.**
The diagnostic now uses `Familia::Encryption.manager.provider` and the
provider's actual metadata readers.

<a id="claude-workflow-public-trigger"></a>
**6. Claude workflows used a mutable action ref — Partially resolved.**
Both workflows now pin `anthropics/claude-code-action` to the immutable
v1.0.211 release commit SHA, resolving the mutable-ref supply-chain risk.

The comment-driven workflow still accepts `@claude` triggers on public comment
and issue events while providing `CLAUDE_CODE_OAUTH_TOKEN` and `id-token:
write`, without a visible collaborator or author-association gate. That
remaining exposure requires a workflow threat-model review; it is distinct
from the resolved action-pinning defect.

### LOW

**7. Unused `stringio` runtime dependency and version cap — Resolved.**
The gemspec no longer declares `stringio`, removing both unused dependency
surface and the future default-gem resolution constraint.

**8. Unused `csv` runtime dependency — Resolved.**
The gemspec no longer declares `csv`.

## Refuted candidates

These conclusions remain unchanged:

- **rbnacl version floor (development only):** cryptography is provided by
  libsodium; an incompatible rbnacl version fails loudly rather than silently
  weakening encryption. The optional dependency remains intentional.
- **`connection_pool` spanning 2.x–3.x:** Familia uses no `connection_pool`
  APIs itself; checkout behavior is supplied by consumer-authored providers.

## Verification limits

Focused non-database tryouts passed for permission encoding, encryption salt
rotation, encrypted fields, single-use redaction, and verifiable identifiers.
Database-backed tryouts could not run in this environment because the configured
Valkey endpoint at `redis://127.0.0.1:2525` failed socket setup with
`Invalid argument - setsockopt(2)`. The open database-backed findings were
therefore confirmed by source inspection and targeted reproductions where
possible, not by the local Valkey test suite.
