# Familia Code Audit — 2026-07-19 (historical public summary)

**Scope at audit time:** familia gem v2.11.2, `lib/` (~32.7k LOC), test suite,
and CI workflows.

## Historical resolution status

**Verified 2026-09-04:** all findings in this public summary are resolved on
`main`. HIGH and MEDIUM fixes merged in [PR #361](https://github.com/delano/familia/pull/361)
on 2026-07-29 and were released in [v2.12.0](https://github.com/delano/familia/releases/tag/v2.12.0).
The two dependency findings and all six follow-up issues are also closed.

This redacted summary records the audit's v2.11.2 snapshot and the resolutions
made from it; it is not a current security assessment. Current per-finding
status is recorded in the [2026-07-26 audit](2026-07-26-audit.md). It
intentionally omits unverified candidates from the original internal review.
The [2026-07-30 delta audit](2026-07-30-audit.md) records a later, separate
finding that was subsequently fixed in
[PR #372](https://github.com/delano/familia/pull/372).

## Confirmed findings

Each HIGH and MEDIUM finding below was fixed in a separate commit on
`fix/security-audit-20260719` before that branch merged as PR #361.

### HIGH

**1. Batch writes bypassed field-type semantics** —
`lib/familia/horreum/persistence.rb` (`multi_field_update`,
`multi_field_fast_write`). Values were serialized and written directly,
bypassing the field setters: an encrypted field given a raw string persisted
it as plaintext, and transient (never-persist) fields were written to the
database. _Fixed:_ a persistence guard now raises `ArgumentError` for
transient fields and for encrypted fields given anything other than nil or an
already-concealed value.

**2. `category_score_range` ignored its category** —
`lib/familia/features/relationships/score_encoding.rb`. The method discarded
the category mask and returned the full time window, so a range query for any
category matched entries of every permission level. A bitmask category is not
expressible as a contiguous sorted-set score range. _Fixed:_ method removed
(it had no callers); use `score_range` plus `filter_by_category` /
`meets_category?` post-filtering.

**3. Permission API failed open on unknown symbols** —
`lib/familia/features/relationships/score_encoding.rb` (`add_permissions`,
`remove_permissions`, `permission?`, `permission_range`, `score_range`,
`encode_score`). Unknown permission symbols were silently treated as no
permission, so a typo in a revocation call was a silent no-op that left the
permission granted. The API also had no test coverage. _Fixed:_ all symbol
lookups now raise `ArgumentError` on unknown symbols; the permission API
surface is test-covered.

### MEDIUM

**4. `decr` / `decrby` raised on every call** —
`lib/familia/horreum/database_commands.rb`. One used the string-command
signature against a hash field, the other called a nonexistent client method;
both (and their aliases) were unusable. _Fixed:_ both use `HINCRBY` with a
negated amount.

**5. `encryption_info` raised on every call** —
`lib/familia/features/encrypted_fields.rb`. The diagnostic called a
nonexistent `Familia::Encryption.current_provider` and phantom provider
accessors. _Fixed:_ rewritten against the real manager/provider API with the
same returned-hash contract.

**6. CI actions pinned to a mutable ref** — `.github/workflows/claude.yml`,
`.github/workflows/claude-code-review.yml`. Both workflows ran
`anthropics/claude-code-action@beta` — a moving branch — while holding a
repository secret and OIDC write permission. _Fixed:_ pinned to the immutable
v1.0.183 release commit SHA, including the required beta→v1 input migration.
The workflows have since advanced to the immutable v1.0.211 release commit SHA.

### LOW

**7–8. Unused runtime dependencies** — `familia.gemspec` declared `csv` and
`stringio` with zero usage in the shipped library; the `stringio` upper bound
also capped a Ruby default gem and would break resolution on future Rubies.
_Resolved:_ [#354](https://github.com/delano/familia/issues/354) was closed
when [PR #378](https://github.com/delano/familia/pull/378) removed both
runtime dependencies.

## Resolved robustness and test-quality follow-ups

The following low-risk candidates were spot-verified, filed publicly, and
subsequently resolved:

- [#355](https://github.com/delano/familia/issues/355) — `MultiResult` raised
  `NoMethodError` on nil results (WATCH-aborted MULTI). Resolved in
  [PR #376](https://github.com/delano/familia/pull/376): aborted transactions
  now report an empty result array and `aborted?` status.
- [#356](https://github.com/delano/familia/issues/356) — `derive_key` mutated
  the caller's context string in the secure XChaCha20 provider. Resolved in
  [PR #375](https://github.com/delano/familia/pull/375).
- [#357](https://github.com/delano/familia/issues/357) —
  `SingleUseRedactedString#expose` without a block destroyed the secret.
  Resolved in [PR #374](https://github.com/delano/familia/pull/374): misuse
  raises without consuming the secret.
- [#358](https://github.com/delano/familia/issues/358) — `connection_provider`
  documentation returned an already-checked-in connection. Resolved in
  [PR #377](https://github.com/delano/familia/pull/377).
- [#359](https://github.com/delano/familia/issues/359) — `ConcealedString`'s
  finalizer claimed to wipe memory but was unconditionally a no-op. Resolved in
  [PR #373](https://github.com/delano/familia/pull/373): the finalizer was
  removed and the documentation now states the actual reference-release
  behavior.
- [#360](https://github.com/delano/familia/issues/360) — timing-dependent tests
  flaked on loaded CI runners. Resolved in
  [PR #383](https://github.com/delano/familia/pull/383) with deterministic
  synchronization and bounded monotonic polling.

## Refuted candidates (no action)

These conclusions remained valid when this historical status was verified on
2026-09-04:

- **rbnacl version floor (dev-only)** — the crypto lives in libsodium, not the
  gem; an old rbnacl fails loudly rather than degrading silently, and the
  soft-require is deliberate optional-dependency design.
- **connection_pool spanning 2.x–3.x** — the library calls no connection_pool
  APIs itself; pool checkout happens exclusively in consumer-authored
  provider lambdas, so the wide range is correctly version-agnostic.
