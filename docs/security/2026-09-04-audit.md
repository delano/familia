## New findings

### MEDIUM — `multi_field_fast_write` can break object and external identifier lookups

**Files:** `lib/familia/horreum/persistence.rb`,
`lib/familia/features/object_identifier.rb`, and
`lib/familia/features/external_identifier.rb`

`multi_field_fast_write` permits `objid` and `extid` fields. It writes the
caller-supplied value before invoking field setters. The setters remove the old
lookup mapping when the identifier changes, but this path does not establish
the new mapping. A partial fast write can therefore leave the stored record
with neither its old nor new object/external identifier lookup entry.

`multi_field_update` already rejects these fields because their setters have
index-maintenance side effects. `multi_field_fast_write` should apply the same
rejection, or perform identifier/index maintenance atomically with the write.
Add coverage for both object and external identifier fields.

### MEDIUM — Instance-scoped SCAN rebuild can populate an index from unrelated scopes

**Files:** `lib/familia/features/relationships/indexing/unique_index_generators.rb`
and `lib/familia/features/relationships/indexing/rebuild_strategies.rb`

An instance-scoped unique-index rebuild falls back to SCAN when it cannot find
a participation relationship or related collection. In that fallback, there is
no durable membership source that can restrict records to the requested scope.
`process_scan_batch` only filters records when it finds a participation
relationship, so the fallback can insert every scanned record into the index
for one instance scope.

The fallback should reject instance-scoped rebuilds that lack a reliable
membership source rather than construct an incorrectly scoped index. Add a
regression tryout that verifies it cannot populate a scope from unrelated
records.

### LOW — Failed index swaps retain temporary keys indefinitely

**File:** `lib/familia/atomic_operations.rb`

`atomic_swap` deliberately preserves the temporary key when `RENAME` fails for
reasons other than a missing source key, then re-raises. These temporary keys
have no expiration and require manual cleanup. This behavior is documented in
`docs/investigation/rebuild-memory-incident.md` but has no automated cleanup or
normal regression coverage.

Decide whether operators need an explicit cleanup command, an expiry policy, or
a durable repair record. Preserve diagnostic evidence if cleanup would obscure
the underlying swap failure.

### MEDIUM — Rebuild paths retain complete working sets in memory

**Files:** `lib/familia/features/relationships/indexing/rebuild_strategies.rb`
and `lib/familia/features/relationships/indexing/multi_index_generators.rb`

Unique-index rebuild paths collect all identifiers before batching. Multi-index
rebuild paths retain loaded objects while processing. Large indexes can therefore
cause unbounded process-memory growth. The behavior and a related incident are
documented in `docs/investigation/rebuild-memory-incident.md`, but streaming
rebuilds are not implemented.

Replace full collection with cursor-driven batching and release each batch before
continuing. Add a bounded-memory integration test or a testable iteration
contract.
